## 2. Cost Implications

- **Default Mode (Current Configuration):** **$0.00 / receipt**. Runs entirely locally using OpenCV + PyMuPDF + Apple Vision (`ocrmac`) on macOS (or Tesseract TSV on Linux/Docker).
- **Optional Selective VLM Escalation (`RECEIPT_ENABLE_CLOUD_VLM=true`):** Only triggered if local extraction produces 0 lines or fails math reconciliation. Uses `Qwen/Qwen2.5-VL-7B-Instruct` via Hugging Face Inference Router (`HF_TOKEN`), estimated at **< $0.001 / escalated receipt** (covered by HF free/PRO monthly credits when enabled).
- **Optional Enterprise Cloud Adapters:** `AzureReceiptProvider` (~$0.01/page), `TextractExpenseProvider` (~$0.01/page), `VeryfiReceiptProvider` ($500/mo starter after 100/mo free tier). All are disabled until credentials are configured.

## 3. Known Limitations & Deployment Instructions

1. **macOS vs Linux/Docker Local OCR:** `ocrmac` uses macOS Apple Vision (`VNRecognizeTextRequest`), which works on macOS hosts (outside strict XPC sandboxes) and is **not** available in Linux Docker containers. On Linux/Docker deployments, install `tesseract-ocr` (`apt-get install -y tesseract-ocr`) or enable `RECEIPT_ENABLE_CLOUD_VLM=true` with `HF_TOKEN` (or configure Azure/Veryfi).
2. **Real-World Handwritten & Extreme Crumple Receipts:** Local text-OCR + spatial clustering handles printed/thermal/PDF receipts well, but handwritten kirana bills or severely crumpled/curved receipts benefit from enabling `RECEIPT_ENABLE_CLOUD_VLM=true` (`Qwen/Qwen2.5-VL-7B-Instruct`) for selective escalation.
3. **Physical Android Verification:** Because no physical Android device is attached to this host via ADB, live camera/PDF upload from Expo Go on Android to `http://192.168.1.31:8001/api/v1/purchases/ocr` must be verified on the user's phone.
